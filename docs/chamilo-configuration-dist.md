# Chamilo 1.11 still has configuration.dist.php from install day

Chamilo 1.11 writes a full copy of the config at install time and leaves that copy in the tree. The leftover is `main/install/configuration.dist.php` still sitting next to the live config, with the install-time database password and the password-recovery key in it.

The file header in the 1.11 tree says the live file is generated by `/install/index.php`, and then:

> configuration.dist.php. That file is an exact copy of the config file at install time.

The template sets `$_configuration['db_password']` and, under “Security word for password recovery”, `$_configuration['security_key']`. On a server that finished the installer, the dist copy holds the generated values from that day, not the `{DATABASE_PASSWORD}` placeholder you see in git.

This is not the Chamilo 3 `.env` check, and it is not “does `main/install/index.php` still answer HTTP”. Do not treat a missing installer URL as proof the dist file is gone. The dist file is a file on disk. This note does not claim it is a public URL.

## On a tree you administer

List names and times. Do not print the file.

```bash
ls -l main/install/configuration.dist.php app/config/configuration.php
```

Your layout may use `app/config/configuration.php` as the live file. Compare that path with the one the vhost actually includes. If the dist copy is absent, record the path you checked and stop.

If it is present:

1. Record size and mtime only.
2. Confirm you can still log in with a test user, so you know which file is live before you move anything.
3. Move the dist copy out of the web tree to root-only storage that your backup policy already covers. Do not paste `security_key` or `db_password` into a ticket, a chat, or a monitoring row.
4. Confirm the live config path still loads and the test user can still open a course.

Rotate `security_key` only after you have confirmed, on that 1.11 build, which recovery links depend on it. This note does not claim that old recovery links die when the file is moved. Moving the copy stops a second file from holding the same secret. Rotation is a separate change window.

I publish these notes while working on [GuardLMS](https://guardlms.com/en/integrations/chamilo). The inventory above is the procedure. It is not a claim that the product runs it for you.
